# Documentation

- Use code, tests, schemas, and runtime behavior as the source of truth.
- Write for the intended reader with prerequisites, commands, expected results, configuration, and operational caveats.
- Keep one canonical explanation and link to it instead of duplicating policy across files.
- Use diagrams for relationships/flows, not decoration. Validate Mermaid syntax and local links where possible.
- Never include real secrets, customer records, or unverifiable product claims.
